# 滴答同步（独立版）

基于原有双来源同步插件另建的滴答清单专用版本。只访问滴答清单 OpenAPI 和思源内核，不包含其他笔记服务的账号、登录、同步或图片下载逻辑。

## 同步内容

| 来源 | 选择规则 | 思源分类标题 | 滴答原任务 |
| --- | --- | --- | --- |
| 收集箱 | 每次读取收集箱当前未完成任务，已归档内容按标识去重；不按任务创建时间排除旧任务 | 滴答收集箱 | 写入思源且读回同步标识后，校验任务未变，再删除原任务 |
| 已完成任务 | 所有可访问清单中，完成时间位于“上次成功同步起点”至“本轮开始时间”的任务，含收集箱中已完成的任务 | 最近已完成任务 | 保留 |

两类内容写入同一个指定思源文档的两个二级标题下，收集箱在前，最近已完成任务在后。每条任务为一行普通正文：“日期时间 + 一个空格 + 内容”。收集箱使用任务创建时间，已完成任务使用完成时间。标题、正文、备注和检查项合并为同一行，多行内容中的换行转换为空格；不再显示引用、逐条来源标签、同步时间或清单 ID。

示例（每行在思源中为独立正文段落）：

```text
滴答收集箱
2026-10-31 09:00:00 记录测试思路
2026-10-31 09:15:00 整理实验照片

最近已完成任务
2026-10-31 10:00:00 完成频响测试
2026-10-31 10:30:00 回复技术支持问题
```

后续同步复用分类标题，在对应区域末尾追加记录，不会每次重复创建标题。接口未提供有效创建时间时显示“时间未知”，不以修改时间或同步时间代替。新版继续识别之前记录的去重标识；已导入的旧引用记录不会自动改写。

## 安装

1. 构建后，停止/关闭思源，将 `dist` 文件夹的内容复制到思源工作空间 `data/plugins/Ultrasonicer-dida-sync/` 中。该目录下直接放置 `plugin.json` 和 `index.js`，不要再套一层 `dist`。
2. 重新打开思源，在集市 → 已下载 → 插件中启用“滴答同步”。
3. 打开本插件设置，填写：
   - 滴答个人 API Token：滴答网页版 → 头像 → 设置 → 账号 → API Token。需要读、写任务权限。
   - 指定文档 ID：右击目标思源文档 → 复制 → 复制块 ID。
   - 已完成任务同步起点：初次默认本地当天 00:00。支持 `2026-10-31 00:00:00` 或带时区的 ISO 时间，可改早以导入历史。
4. 点击顶栏勾号，或从命令面板执行“同步滴答收集箱与已完成任务”。

插件名称为 `Ultrasonicer-dida-sync`，配置键为 `dida-sync-config`，和原版独立。需要手动填写 Token、目标文档和历史起点；不会读取旧版配置。迁移时停用原版的滴答同步，避免两个插件同时操作收集箱。旧版导入的记录没有本版去重标识：初次设置起点时注意历史导入范围。

## 时间、去重与失败恢复

- 已完成任务按 `completedTime` 筛选，不按创建时间、修改时间或截止日期。上下界均包含；边界任务依赖“任务 ID + 完成时间”去重，重复任务的不同完成实例分别记录。
- 本轮结束点在点击同步时固定，成功后把它保存为下次起点，即使本轮没有已完成任务也会推进。同步期间新完成且晚于本轮开始的任务留到下次。
- 官方已完成接口单次最多 200 条，无偏移分页。本插件遇到满页会重叠二分时间范围，合并去重；若一秒范围仍达上限则报错并保留原起点，避免把截断结果当作完成。
- 写入时把隐藏的 `custom-dida-sync-key` 属性与任务正文段落放在同一笔思源操作里，并读回确认。分类标题使用 `custom-dida-sync-section` 属性定位，也会复用文档内已有的同名标题。重新启动、部分写入失败、删除原任务失败后重试，都使用目标文档中的标识跳过已有记录。
- 收集箱记录按任务 ID 与标题/正文/检查项内容摘要去重；删除失败后内容未变只重试删除，内容变更则先补充新记录。移入收集箱的旧任务也会归档。
- 本轮收集箱所有任务先归档，再删除，避免父任务被删导致子任务尚未保存。删除前重新读取任务；若已完成、移到其他清单或正文发生变化，则保留原任务并提示下次重试。校验和删除是两个 API 请求，极短间隔内的并发编辑仍无法由此插件原子锁定。
- 两类同步独立汇报错误；一类失败仍会尝试另一类。已完成接口失败、响应格式异常、写入未确认、配置保存失败时，不推进相应已完成时间游标。
- 若思源已写入但自定义属性无法读回，插件报错并停止删除该类源任务。请先检查页面；在这种内核不兼容情形下，手工重试可能留下重复的无标识内容。
- 去重标识保存在目标文档，删除/清除这些属性后补同步会重新导入；更换目标文档且需要历史时，把已完成起点调早。跨设备不要同时启动同步；本地互斥只阻止当前插件实例重复运行。

## 开发与验证

```powershell
npm install
npm run typecheck
npm test
npm run build
```

`npm run build` 生成 `dist/` 和 `package.zip`，仅写入当前项目，不自动安装或修改思源工作空间。`npm run dev` 在当前项目的 `dist/` 中监视构建。Token 使用密码框展示，只保存在思源的本插件配置文件中（非加密存储），不要分享含 Token 的工作空间或配置备份。

自动测试使用模拟滴答/思源接口，覆盖时间边界、超过 200 条时拆分、重复任务、部分失败、重试去重、删除失败、任务同步中变更及读回确认。测试不访问真实账户，也不删除真实滴答任务；安装后仍需用少量任务验证实际账号及思源内核兼容性。

可选解析器兼容验证：先运行 `npm test`，再运行 `node scripts/verify-lute.mjs "思源安装目录/resources/stage/protyle/js/lute/lute.min.js"`。本次检查结果见 `VALIDATION.md`。

## 接口依据

- [滴答官方 OpenAPI 文档](https://developer.dida365.com/docs/#/openapi)：`GET /project/inbox/data`、`POST /task/completed`（不传 `projectIds`，按 `startDate` / `endDate` 查询全部清单）、任务查询及删除。
- [思源官方内核 API](https://github.com/siyuan-note/siyuan/blob/master/API.md)：文档读取、Markdown 追加、网络代理。

本版不继承旧版缺少必要日期参数的 `/task/undone` 回退；收集箱接口失败会明确报错，不会用空列表假装成功。
